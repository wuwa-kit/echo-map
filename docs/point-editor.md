# 人工点位录入

## 打开录入页

直接通过网站的 `/editor` 打开录入页，也可以从地图筛选面板点击“点位录入”。本机开发时运行 `pnpm dev`，通过 Vite 输出的地址访问。从主地图进入时会继承当前地图中心、缩放、地图、地区、楼层、重力、楼层控件样式、点位来源显示状态；只选择了一种目标声骸时，还会将它设为当前追踪声骸。

本机开发服务仍限定同源访问，并将修改直接写入项目文件。其他环境会自动使用当前浏览器的本地存储，首次打开时以网站已发布的人工点位为基础；修改不会直接写回网站或项目仓库，需要通过“导出”取得 JSON 后再传回项目。

## 两种独立模式

顶部直接切换“声骸录入 · C1 / C3”和“定位点维护”。默认 `/editor` 为声骸模式，定位点模式为 `/editor?mode=navigation`。新增按钮只创建当前类别；两类点位分别显示在当前地图的列表中，可按官方待核验、草稿、已核验筛选，声骸还可筛选清单待补齐。列表分批加载，不需要通过“新增”菜单选择类别。

桌面使用可收起的点位列表、地图、录入表单三栏布局；窄屏可切换地图与列表，下方继续编辑表单。模式、列表状态、C1/C3 筛选和地图视口通过 URL 恢复，临时搜索与草稿不进入 URL。

切换模式会保留各自的草稿、未应用坐标文本和输入错误。已修改的点位分别缓存到浏览器，重新打开后可逐模式恢复；缓存不代表已写入点位库或已通过核验。点击另一类别的地图点位只预览，点击“维护此点”才切换模式。当前模式已有未保存编辑时，先保存草稿或放弃修改再打开其他点位。

编辑坐标、选择点位、恢复或合并草稿、切换模式与楼层均不自动定位。需要查看当前点位时，点击面板中的“定位到此点”；缺少 XY 时按钮不可用。首次打开保留 URL 视口恢复（没有视口时使用默认地图或楼层范围），主动选择地区仍会定位。

## 录入声骸点位

按游戏追踪器录入时，可先搜索并用 C1/C3 快捷筛选选择“当前追踪声骸”，再填写实测 XYZ。只需录入认识的声骸及数量，清单可以一直保持 `partial`。确认全部认识并补齐后，再勾选“怪物清单已补齐”。坐标核验与清单完整程度相互独立。

填写 XYZ 后，系统会自动查找同地图、同楼层、同类点位。默认 XY 距离不超过 30、高度差不超过 8，两个范围均可调整。官方点仅比较 XY，不使用占位 Z 排除候选。

选择“追加到此点”会保留已有怪物，同种声骸取两次数量中的较大值，避免重复追踪造成累加，合并后仍可手动修正数量。追加人工点保留原 XYZ。追加官方点使用本次实测 XYZ，结果写入人工文件，并以 `replacesOfficialIds` 保存不可变的官方原始点位 ID；即使后续官方聚合重新分组，替代关系仍然有效。官方文件保持不变，即使删除官方文件，人工记录仍有完整坐标和清单。

查重始终使用完整有效点位库，不受官方参考点显示开关影响。核验保存有候选时必须选择追加，或明确点击“这些都不是，作为独立新点”，系统不会自动按最近距离合并。没有匹配点时可以直接新建。地图空白处点击不会新增点位或修改坐标。所有新增点位均从面板进入，XYZ 通过面板粘贴或逐轴填写；地图保留已有点位的查看与编辑入口。

## 保存与核验

“保存草稿”常驻底部，允许缺少 XYZ、尚未添加怪物或暂未处理附近候选。再次核验保存时仍需处理重复点。已保存的声骸草稿追加到人工点后，在同一次保存中合并清单并移除原草稿，避免留下重复记录。“核验并保存”要求完整坐标和至少一种已知怪物，不要求认全怪群。人工草稿不会发布到地图或路线。

“核验保存，继续下一处”会保留地图、地区、楼层和追踪声骸，清空 XYZ，并预填当前追踪声骸 1 只。“复制到新点”保留清单，清空 XYZ 和官方替代关系。

## 定位点维护

优先从列表选择官方待核验点。点击官方点只显示来源、参考坐标与 Z=0 占位说明；点击“录入实测数据”才创建人工补录草稿，并清空 Z。官方文件保持不变，人工记录保留原始官方 ID。缺失点位可通过“新增人工定位点”补充。

定位点使用独立表单维护名称、类型和传送能力，这些关键字段始终展开。BOSS、副本与挑战按项目规则自动设置为可直接传送。附近定位点只提供查看和维护，不套用声骸追加清单操作；核验新点前需要处理候选或确认独立新点。

“核验保存，查看下一待核验点”保存成功后，打开同地图、同楼层与重力状态下的下一处官方定位点预览。

人工定位点需要核验图标点位 XYZ，才能作为路线起点。可直接传送的定位点还可填写实际传送落点 XYZ；留空时明确提示按图标点位计算。落点 XY 在编辑地图中以青色空心圆显示，核验保存要求填写完整实测 XYZ。修改为不可传送会清除不再适用的落点数据，复制点位和切换地图会同时清空两组坐标。

## 写盘、历史与导入导出

本机开发服务会把保存内容直接写入人工文件；线上页面则保存到当前浏览器，并通过“导出”取得 JSON。未保存内容可通过浏览器草稿缓存恢复。

写盘采用顺序执行、修订校验和临时文件替换。出现版本冲突时会保留编辑内容，需要重新载入点位库、核对记录后再次保存。不要同时运行多个录入服务写入同一份文件。

录入页支持 JSON 导入、导出、删除撤销和历史版本恢复。导入导出默认只处理当前模式，混入另一类别的导入文件会被拒绝；导入确认时保留另一类已保存点位和未保存草稿。“整库历史”明确用于恢复两类点位，另一模式尚有未保存编辑时会阻止恢复。导入与恢复都会先显示新增、修改、移除数量及作用范围，确认后写入。

本机开发服务的保存前快照位于 `data/cache/point-history/`；线上页面的快照位于当前浏览器。界面显示最近 50 个不同版本。缓存与历史都不应视为备份，重要数据需要及时导出。正式人工文件可纳入 Git 管理。

## 地图与详情展示

地图上的单个声骸点位使用菱形头像，相邻点位聚合后使用圆形头像，均不显示数量文字。标记按怪群组成分为单只 C1、单只 C3、多只纯 C1、包含 C3 的多只怪群四档尺寸；多声骸标记保持在 BOSS 标记以下。头像按当前筛选命中的声骸种类合成，同种去重，最多展示 4 种。录入与详情预览在超过 4 种时显示 3 个头像及其余种类数。

录入地图与主地图共用点位渲染规则。C4 BOSS 使用普通菱形头像，周本 BOSS 使用切角菱形头像，其他定位点复用对应官方图标；缩放阈值、前后景层级、楼层角标和地区文字也保持一致。为了便于逐点编辑，录入地图的声骸不做聚合，当前草稿以金色选中框始终置顶显示。点击重叠位置时先显示“此处点位”候选列表，不再只取最先命中的一个点。

地图导航与重力切换位于画布左上角，视口附近的楼层切换和指针 XY 位于左下角，与主地图使用同一组组件及楼层覆盖判断。选择地图区域会同步草稿的地图与地区，并回到地表；右侧详情栏不再重复提供地图、地区、楼层和重力表单。

点击聚合图标时，先列出各点位，再查看完整怪物清单。筛选命中的怪物会高亮标注“目标”。人工清单尚未补齐时显示“已录入 2 种 · 4 只”和“可继续补录”，补齐后显示“共 2 种 · 4 只”。总数统计整份清单，每种怪物单独显示数量。

官方测试点的每个原始标记按 1 只显示；相邻标记合并后按声骸种类汇总。数量以“只”计，路线以“处”为一站，同处混合 C1/C3 不会重复编号。

定位点详情分别显示图标点位与传送落点。存在实测落点时，路线及长图从落点开始，并以青色空心标记表示；地图上的定位图标仍保留在原始图标位置。
