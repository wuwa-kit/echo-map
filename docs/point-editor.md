# 人工点位录入

## 新增和修改

从地图筛选面板点击“点位录入”，在“定位点”和“声骸点位”之间切换。录入面板与主地图共用同一张地图。

点击“新增点位”填写新记录，点击地图上的人工点位可编辑已有记录。官方声骸点位只读，保留来源及 Z=0 占位高度说明。

填写整数 XYZ、选择楼层，并补充点位信息：

- 声骸点位：添加声骸及数量，至少填写一种声骸。
- 定位点：填写名称、选择图标和传送能力；选择类型后会应用该类型的名称、图标和传送规则。
- 可传送定位点：可以补充实际传送落点 XYZ；留空时路线使用图标点位坐标。

点击“保存”后，系统检查字段完整性、坐标格式和数据引用，通过后更新点位。没有单独的核验步骤或核验状态；坐标的真实性由录入者确认。

新增定位点时可勾选“保存后继续新增”，保存成功后清空坐标并保留点位类型，方便连续录入。修改已有点位时，保存后仍停留在当前记录。已保存点位可以删除，删除后短时间内可撤销。

## 未保存的编辑

尚未保存的内容只保留在当前页面的内存中，刷新或关闭页面后丢弃，不提供自动暂存或恢复。切换声骸、定位点两类表单会保留各自的输入，切换正在编辑的人工点位时会提示保存或放弃修改。

不完整内容不能写入点位库。输入有误或保存失败时，表单保留原内容，修正后再次保存。“返回”结束本次录入并清空未保存表单。

## 数据保存位置

运行 `pnpm dev` 并通过本机 localhost 访问时，人工定位点保存在 `data/manual/navigation/`，人工声骸保存在 `data/manual/echo/`。两类数据均按地图拆分，主地图再按二级地区拆分，详见 [数据目录与归区](./data.md#点位分片与归区)。文件只保存完整点位，没有 `draft`、`verified` 等状态。地区根据地图与 XY 自动判断，录入时无需填写或保存。

开发服务直接读取源文件提供地图点位数据。生产构建会自动生成 `public/data/custom-echo-points.json`、`public/data/custom-navigation-points.json` 和 `public/data/official-echo-points.json`；这些发布文件已被 Git 忽略，日常录入只会产生人工源文件的 Git 改动。

在线上页面录入时，点位保存到当前浏览器，可以导出后带回项目。未保存的表单内容不会进入导出文件。

## 导入、导出与历史快照

“导出”包含全部已保存的人工点位。“导入”会先校验文件，再显示新增、修改、删除数量；确认后替换完整人工库。两类表单都没有未保存修改时才可导入。

本机写盘保留保存前快照，位于 `data/cache/point-history/`，不纳入 Git。保存按文件检查内容版本：修改不同分片的页面可以分别保存，同一分片已被其他页面更新时提示冲突并保留编辑内容。跨区移动同时更新源和目标文件，写盘失败时恢复已经修改的文件。完整库导入会检查全部分片版本，防止覆盖其他页面新增的点位。分片写盘队列仅协调同一开发服务进程中的请求。
