# 数据来源与结构

## 收录边界

项目只收录至少属于一个合鸣套装的 C1/C3 声骸，不收录 C4 BOSS、宝箱、采集物、任务、解谜和其他普通怪物。BOSS 仍会作为可传送定位点显示。传送点、局部交通、入口、秘境或挑战和服务地标等定位点全部启用，不提供手动显示筛选。

人工点使用实测整数 XYZ。可直接传送的定位点可额外记录 `teleportCoordinate` 作为实际传送落点；缺省时路线回退使用图标点位 XYZ。官方点转换为相同录入结构，Z=0 为占位值。

JSON 文件、点位导出和开发服务响应在序列化时省略对象中值为 `null` 的字段，读取时由数据校验恢复为空值；运行时仍使用完整结构。数组中的 `null` 保留位置，`0`、`false` 和空字符串照常写出。坐标缺失仍无法通过保存校验。

## 数据来源

- 声骸与合鸣效果：库街区 Wiki 公开目录接口；套装成员来自 Wiki 套装详情页的“对应声骸”。
- 地图瓦片、分层、图标和临时 XY：库街区官方地图公开静态资源。
- 人工点位与精确 XYZ：`data/manual/navigation/` 和 `data/manual/echo/`，由录入系统维护。
- 官方点位：`data/generated/official-echo/`，Z=0，每个原始官方标记的占位数量为 1 只；相邻标记合并后按声骸种类汇总。原始声骸点位由地图同步写入紧凑的 `data/generated/official-locations.json`。
- 地图类型别名：`data/config/map-echo-aliases.json`，由人工审阅。
- 定位点收录和传送能力：`data/config/map-navigation-types.json`，由人工审阅。
- 重复定位点图标的分组名称：`data/config/map-navigation-icon-groups.json`，由人工审阅。

## 同步与匹配

同步脚本读取每个 Wiki 套装详情页的“对应声骸”模块，按 COST 1/3 分组构建成员关系，并与声骸目录的 COST 标签交叉校验。目录的“套装”标签和地图的套装成员关系不参与归属计算。详情链接使用字符串条目 ID 精确匹配目录；链接指向敌人词条时，读取该词条标题后匹配唯一同名声骸。缺少模块、未知成员或 COST 冲突会中止同步。定位点显示分组按下载后图标内容的 SHA-256 指纹合并。无法与白名单精确匹配或无法通过显式别名匹配的官方怪物会被拒绝，不会进入声骸数据。

`data/generated/wiki.json` 的 `sonatas` 数组保留[官方 Wiki 合鸣效果目录](https://wiki.kurobbs.com/mc/catalogue/list?fid=1099&sid=1219)接口的显示顺序。`public/data/catalog-data.json` 使用官方地图 `catalogRelation.json` 的套装 ID 倒序排列，地图筛选和资产库沿用此顺序；排序不改变 Wiki 成员关系。每个合鸣套装包含 `c1EchoIds`、`c3EchoIds`，分别列出该套装的 C1、C3 声骸 ID，例如 `wiki-echo-11231`。没有对应声骸时为空数组。这两个列表由声骸的 `sonataIds` 和 `cost` 自动反向生成、去重并按 ID 排序，数据校验要求双向归属一致，不手工维护列表。

`pnpm data:sync:map` 在发布前自动重建 `data/generated/official-echo/`，确保 Wiki 白名单变化后不会引用旧声骸；人工点位不受此重建影响。

官方声骸仅收录固定地图范围：主地图的今州、拉古那、七丘、冰原地表、黑海岸，以及既有独立地图 `900`、`902`、`903`、`905`、`906`、`909`、`910`。梦州及其独立地图梦枢天罗（`912`）不收录官方声骸。新增独立地图和主地图新增二级地区默认不引入，范围由 `src/domain/official-echo-scope.ts` 统一控制，同步、转换、发布和校验均使用此范围。

排除的官方声骸不写入原始点位快照或转换分片。地图底图、楼层、地区导航和声骸图鉴仍正常同步，人工录入不受官方声骸收录范围限制。

当前官方资源 hash 会在每次同步时动态获取。底图瓦片运行时直接读取官方 WebP 静态资源。`public/vendor/kuro-map/` 已预留为可选本地缓存目录并被 Git 忽略。

## 公开数据文件

`public/data/` 中与地图加载相关的五个 JSON 文件均为紧凑格式：

- `map-data.json`：地图结构、地表与分层瓦片、地区导航、文字标签、楼层连接及地图来源信息。
- `catalog-data.json`：声骸、合鸣套装、定位点图标分组、定位点类型、图标定义、目录来源和同步统计。声骸按中文名称匹配完整 Wiki 图鉴并兼容已配置别名。点位通过 `echoId` 直接复用图鉴头像，不保存官方地图的声骸图标。传送点、BOSS 等定位点通过 `iconId` 引用 `pointIcons`。
- `official-echo-points.json`：官方声骸的 `locations` 原始位置和 `library` 转换点位。
- `custom-echo-points.json`：已保存的人工声骸点位。
- `custom-navigation-points.json`：已保存的人工定位点。

`official-echo-points.json`、`custom-echo-points.json` 和 `custom-navigation-points.json` 是自动生成的发布文件，不纳入 Git 跟踪。地图同步、官方转换和生产构建会生成这些文件，内容未变化时不重写；`pnpm build` 将公开数据复制到 `dist/data/`。本地开发直接从源文件提供相同的 JSON 请求，录入保存只更新受影响的人工点位分片，不会重写发布文件或其他分片。

开发服务与发布站点使用相同的请求路径和结构。地图、图鉴与官方声骸数据并行读取；人工声骸与定位点数据按类别读取。录入接口和导入导出处理完整人工点位库，保存前会检查坐标完整性、声骸数量、定位点信息及地图引用。前端继续复用底图、楼层与声骸图鉴素材。

## 官方点与人工点

官方与人工数据使用相同的点位结构。`data/manual/navigation/` 和 `data/manual/echo/` 分别保存人工定位点和声骸点，`data/generated/official-echo/` 保存官方声骸转换数据。点位没有草稿或核验状态字段；人工库中的记录均经过保存校验，未完成的表单只保留在当前页面内存中，刷新或关闭页面后丢弃。官方点通过 `officialIds` 保留来源，人工替代关系通过 `replacesOfficialIds` 表达。

`note` 是可选的人工备注。官方转换不再逐点保存模板说明或固定的 `compositionStatus: "partial"`；来源标识和合并数量由 `officialIds`、`members` 提供。运行时将缺省备注视为空文本、缺省清单状态视为未补齐，发布 JSON 也保持这些字段缺省。官方点仍明确保存 Z=0，人工备注和已补齐状态照常保留。

定位点的 `coordinate` 表示图标点位 XYZ，只有 `mode: "fast-travel"` 可以携带可选的 `teleportCoordinate`。后者表示角色传送后的实际落点 XYZ，不改变地图图标位置；路线起点使用 `teleportCoordinate ?? coordinate`。官方转换不会把图标坐标重复写成落点，未实测时保持字段缺省。

官方点的 XY 取官方坐标除以 100 后四舍五入，Z 固定为 0，并保留全部原始 ID。声骸点的大区使用下述共享归区逻辑推导，原始来源记录保持不变。官方声骸记录再按地图、大区、楼层和重力状态分组，使用未取整的原始 XY 进行直径上限为 25 的确定性合并。同一组内任意两个来源点的距离都不得超过 25，避免通过中间点链式合并远处点位。输出坐标选择最靠近组中心的真实来源点，不创建虚构坐标。每个原始官方标记按 1 只计数，合并后的同种声骸数量为其来源标记数，清单默认未补齐。

地图和路线规划统一使用合并后的人工、官方点位库，按地图、楼层、重力和声骸选择显示，不再按点位来源筛选。人工点通过 `replacesOfficialIds` 替代的官方点会自动去重，官方点在录入面板中保持只读。

删除 `data/generated/official-echo/` 即可停用官方转换点位。加载和构建会将缺失目录视为空库，不会回退显示旧地图快照里的点，人工文件不受影响。公开的官方声骸文件缺失时，前端会将其视为空数据。

`pnpm data:validate` 聚合并校验三类分片，检查坐标、引用、全库 ID 唯一性和文件归区。

## 点位分片与归区

三类数据均按物理地图拆分。主地图 `8` 再按二级地区拆分；独立地图直接使用 `stateId.json`。文件只在有点位时创建，每个文件仍为 `{ "version": 1, "points": [...] }`，点位按 ID 排序。

官方点位分片使用单行紧凑 JSON；人工点位分片保留两空格缩进，便于阅读和协作修改。

```text
data/
├─ manual/
│  ├─ navigation/                # 人工定位点
│  │  ├─ 8/
│  │  │  ├─ 1-1.json              # 瑝珑·今州
│  │  │  ├─ 1-8.json              # 瑝珑·梦州
│  │  │  ├─ 3-3.json              # 黎那汐塔·拉古那
│  │  │  ├─ 3-4.json              # 黎那汐塔·七丘
│  │  │  ├─ 4-6.json              # 罗伊冰原·冰原地表
│  │  │  └─ 900.json              # 黑海岸
│  │  ├─ 900.json                # 泰缇斯之底
│  │  ├─ 902.json                # 下层金库
│  │  ├─ 903.json                # 阿维纽林
│  │  ├─ 905.json                # 隐海试验场
│  │  ├─ 906.json                # 拉海洛
│  │  ├─ 909.json                # 黯原
│  │  ├─ 910.json                # 时隙废都
│  │  └─ 912.json                # 梦枢天罗
│  └─ echo/                      # 人工声骸，相同目录规则
└─ generated/
   ├─ official-echo/             # 官方声骸，相同目录规则
   └─ official-locations.json    # 官方原始点位快照
```

上图列出可用路径，空分片及其目录不需要预建。主地图文件名使用稳定的 `countryId-groupId`；无分组的黑海岸使用 `900`。名称来自地图导航元数据，改名不影响文件名。

点位记录只保存 `stateId` 和 XYZ，不保存 `countryId` 或二级地区字段。共享归区函数供分片保存、地图显示和路线导出使用：

- 独立地图根据地图导航关系直接找到所属分组。例如 `912` 属于梦州，坐标不参与归区。
- 主地图将 XY 转为地图坐标，找同地图最近的分组直属地区名称坐标，采用该名称所属的二级地区。三级小地区名称不参与判断；黑海岸整体归为一个地区。
- 主地图归区是最近名称坐标的推导，不是行政边界多边形判断。所有用途沿用相同结果。

保存只修改受影响的文件；跨区移动保留点位 ID，同时更新源和目标分片，源分片清空后删除。不同分片可并发保存，同一分片以内容版本检测冲突。导入仍处理完整人工点位库，校验全库版本后只写出有变化的分片。生产构建只聚合分片，不重写人工源文件。

## 官方测试点与旧 XYZ 示例

`data/manual/locations.json` 中包含少量 `quality: "example"` 的声骸和定位点示例。示例 Z 只用于演示路线算法，不能视为实测坐标。定位点通过 `officialLocationId` 继承同步配置中的类型和传送能力，不从坐标推断是否可传送。

以下是旧同步脚本使用的示例格式。正式录入请使用地图中的“点位录入”面板：

```json
{
  "id": "my-location-id",
  "echoName": "先锋幼岩",
  "officialLocationId": "官方点位 ID，可选",
  "stateId": 8,
  "countryId": 1,
  "levelId": null,
  "x": -497,
  "y": 449,
  "z": 18,
  "quality": "manual",
  "note": "游戏内实测"
}
```

有 `officialLocationId` 时会覆盖对应临时点位，没有时会创建独立人工点位。分层位置还应填写官方楼层 ID，例如 `-1/3`。
